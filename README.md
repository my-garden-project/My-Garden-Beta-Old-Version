# My Garden — Beta (old educational version)

Навчальний знімок мобільного Flutter-застосунку **«Мій город» / My Garden**.
Репозиторій призначений для розробників, які вивчають структуру Flutter-проєкту,
стан застосунку, локальне збереження даних, роботу з камерою, каталогом культур і
побудову адаптивного мобільного інтерфейсу.

> Це окрема стара beta-версія для навчання. Вона не є поточною production-версією
> продукту й не повинна використовуватися для публікації застосунку без перевірки.

## Що вміє застосунок

- створювати городи й ділянки у вигляді сітки;
- додавати культури до клітинок і вести історію посадок;
- показувати каталог культур, етапи вирощування та рекомендації з догляду;
- формувати нагадування про полив, дозрівання і збір;
- вести щоденник росту з фотографіями;
- зберігати запаси насіння, добрив і засобів захисту;
- сканувати пакування камерою пристрою;
- зберігати дані локально без обов'язкового сервера.

## Технологічний стек

| Частина | Технологія | Для чого використовується |
|---|---|---|
| Мобільний клієнт | Flutter, Dart | Один код для Android та iOS |
| Інтерфейс | Material 3 | Екрани, навігація, форми й адаптивність |
| Стан застосунку | `ChangeNotifier` | Оновлення даних та інтерфейсу без зовнішнього state-management пакета |
| Локальне сховище | `shared_preferences` | Профіль, ділянки, посадки, налаштування й нагадування |
| Каталог | JSON у `assets/data` | Дані культур, джерела та рекомендації |
| Камера і сканування | `mobile_scanner`, `image_picker` | Штрихкоди, фото рослин і врожаю |
| Файли | `path_provider` | Доступ до локальних директорій застосунку |
| Зовнішні посилання | `url_launcher` | Відкриття джерел і контактів |
| Якість | `flutter_lints`, `flutter_test` | Статичний аналіз та автоматизовані тести |

## Структура репозиторію

```text
lib/
  main.dart                 точка входу
  src/
    app/                    оболонка і навігація
    screens/                екрани застосунку
    widgets/                повторно використовувані віджети
    catalog/                каталог культур і фото
    calendar/               календарна логіка
    diary/                  щоденник росту
    feedback/               відгуки користувача
    monetization/           демонстраційні рекламні блоки
    models.dart             моделі даних
    app_state.dart          стан і бізнес-операції
    storage.dart            локальне збереження
assets/
  branding/                 іконка й фірмові матеріали
  data/crop_catalog/        JSON-база культур
  images/crops/             фото культур
android/                    Android-конфігурація
ios/                        iOS-конфігурація
test/                       автоматизовані тести
```

## Що потрібно встановити

1. [Flutter SDK](https://docs.flutter.dev/get-started/install) зі стабільного каналу.
2. Android Studio з Android SDK — для Android.
3. Xcode — для iOS (потрібен macOS).
4. Git і редактор коду, наприклад VS Code або Android Studio.

Перевірте середовище:

```bash
flutter doctor
flutter devices
```

## Перший запуск

```bash
git clone https://github.com/PolinaSnihurska/My-Garden.git
cd My-Garden
flutter pub get
flutter run
```

Якщо під'єднано кілька пристроїв:

```bash
flutter devices
flutter run -d DEVICE_ID
```

### Запуск на Android

1. Запустіть Android Emulator або під'єднайте телефон із USB debugging.
2. Виконайте `flutter run`.
3. Для тестового APK виконайте:

```bash
flutter build apk --debug
```

Файл з'явиться в `build/app/outputs/flutter-apk/app-debug.apk`.

### Запуск на iOS

1. Відкрийте iOS Simulator або під'єднайте iPhone.
2. Виконайте `flutter run`.
3. Для фізичного iPhone відкрийте `ios/Runner.xcworkspace` у Xcode та виберіть
   власну команду в **Signing & Capabilities**.

Release-збірка для iPhone потребує Apple signing certificate і provisioning
profile. Їх навмисно немає в репозиторії.

## Рекомендований порядок вивчення

1. Почніть із `lib/main.dart` і простежте створення застосунку.
2. Перегляньте `lib/src/models.dart` — це основні сутності продукту.
3. Вивчіть `lib/src/storage.dart`, щоб зрозуміти локальне збереження.
4. Перейдіть до `lib/src/app_state.dart` і простежте бізнес-операції.
5. Оберіть один екран у `lib/src/screens` та знайдіть пов'язані віджети.
6. Запустіть тести, змініть невелику функцію й додайте власний тест.

## Правила роботи команди

- Не додавайте паролі, токени, сертифікати та файли `.env` у Git.
- Створюйте окрему гілку: `feature/коротка-назва` або `fix/коротка-назва`.
- Перед pull request запускайте форматування, аналіз і тести.
- Не змінюйте структуру JSON-каталогу без одночасного оновлення моделей і тестів.
- Не використовуйте агрономічні рекомендації як професійну консультацію без
  перевірки профільним фахівцем.

## Обмеження цієї beta-версії

- дані зберігаються лише локально на пристрої;
- немає серверної авторизації, синхронізації та адміністративної панелі;
- сканер і фото потребують реального пристрою та дозволу камери;
- погода, партнерські пропозиції й частина рекомендацій мають демонстраційний
  характер;
- перед production-релізом потрібні security review, юридична перевірка,
  агрономічна валідація та окрема політика приватності.

без перевірки джерела й прав.
